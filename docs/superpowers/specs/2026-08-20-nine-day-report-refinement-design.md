# 九天课程报告精修设计

## 目标

在不虚构实现、实测、录屏或人工验收的前提下，精修 `docs/reports/` 中九份报告，使互评者能够快速判断每天的范围、验收结果、问题处理和下一步交付，并能依据报告继续推进项目。

## 评分导向

精修按以下顺序组织信息：

1. 范围：当天做什么、不做什么，以及九天项目边界是否可控。
2. 验收：使用“前提 -> 操作 -> 可观察结果 -> 结论”的完整表述。
3. 场景与完成方式：说明竞赛现场用途，并明确项目为独立完成。
4. 问题、计划与 AI 沟通：记录真实问题、有效或无效的助手沟通，以及可检查的次日交付物。
5. 证据：保留截图、命令、测试结果和提交记录，但让结论先于证据细节。

## 统一日报结构

第 1 至第 8 天原则上采用以下结构，并按当天内容适度合并：

1. 基本信息与今日目标。
2. 今日范围或交付物。
3. 方案、实现或关键决策。
4. 验收记录，优先使用表格表达前提、操作、预期、实际和结论。
5. 今日证据，引用现有截图、命令或测试事实。
6. 问题与处理，区分已解决问题和仍受环境限制的问题。
7. AI 沟通记录，只写现有材料能够佐证的过程，不虚构提示词原文。
8. 自检与明日计划，将下一日工作写成可检查的文档、代码、测试或演示产物。

第 9 天继续采用结课报告结构，但把最终范围、验收结论和未完成项前置；删除正文与附录之间无助于判断的重复内容。

## 每日叙事重点

| 天数 | 精修重点 |
| --- | --- |
| 第 1 天 | 补足竞赛现场场景；将两类业务打印写清；细分必做与不做；增加成功、端口占用、服务未启动和打印失败四类验收。 |
| 第 2 天 | 突出三类方案比较、选择依据、组件责任和可交给下一日实现的接口/状态机产物。 |
| 第 3 天 | 突出 Job 契约、FIFO 主路径、失败语义、重启恢复和 at-least-once 边界。 |
| 第 4 天 | 突出 API 与 Mock Web 已形成可操作闭环，同时明确 Fake Renderer/Fake Printer 的演示边界。 |
| 第 5 天 | 以三张真实 PDF 截图和前提-操作-结果表为核心，压缩重复的底层安全细节。 |
| 第 6 天 | 区分代码完成、受控命令测试、交叉编译、系统队列接受和物理出纸五种证据层级。 |
| 第 7 天 | 以真实缺陷的“现象-根因-修改-复测”闭环为主，压缩测试目录式罗列。 |

| 第 9 天 | 前置最终结论；保留架构、核心实现、验收和问题复盘；合并重复的范围/完成情况/证据表。 |

## AI 沟通写法

每篇只记录一个最能说明方法改进的例子。可使用现有报告已经体现的事实，例如：

- 限制助手不得假定 CCPCOJ 未确认的接口。
- 纠正“命令返回成功等于物理出纸”的错误口径。
- 将只扫描 JavaScript 源码字符串的弱验证改为 Node VM 行为测试。
- 纠正“交叉编译等于 Linux 实测”的证据越界。
- 明确 Codex 只读审查不能替代真人同学启动验收。

表述重点是输入约束如何改变输出质量，不写无法核验的逐字提示词，也不声称 AI 独立完成项目。

## 事实边界

- 保留项目为独立完成的现状，不加入双人成员分工。
- `demo` 的 `succeeded` 仅表示 Fake Adapter 接受调用。
- `platform` 的 `succeeded` 仅表示平台命令成功返回，不自动表示物理出纸。
- Windows 受控 runner 不是系统打印队列实测。
- Linux 交叉编译不是 Linux/CUPS runtime 实测。
- Day 5 保存的 Chrome/PDF 截图可以作为历史实跑证据；Day 7 的受限环境失败必须继续标明。
- 当前没有 Windows/Linux 录屏和真人同学仅看 README 的记录，报告不得改写为完成。
- 测试统计、版本、端口、状态名和错误码以仓库当前报告与代码为准。

## 编辑原则

- 保留现有图片路径，不生成替代性证据图。
- 不加入账号、密钥、绝对本机路径或新的外链堆砌。
- 使用短段落和表格提高扫描效率，避免同一安全边界在一篇中重复多次。
- 测试名只保留能支撑关键结论的代表项，其余用统计或类别概括。
- 不为追求篇幅而扩写；每一段必须服务于范围、验收、推进或证据判断。

## 完成标准

1. 九篇报告均能直接识别当天目标、完成边界、验收结果、问题和下一步。
2. 第 1 至第 8 天均包含可核验的验收表达和 AI 沟通记录。
3. 明日计划均包含具体产物；第 9 天改为后续补验与归档计划。
4. 图片引用、Markdown 链接和代码块保持有效。
5. 九篇之间的端口范围、状态机、平台证据和完成情况不存在矛盾。
6. 全文无占位符，无虚构录屏、Linux/CUPS 实跑、Windows 系统队列或真人验收。
