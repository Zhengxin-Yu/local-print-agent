# 项目交接文档设计

## 目标

生成仓库根目录的 `PROJECT_HANDOFF.md`，供 Code Buddy 在不了解历史对话的情况下继续开发、补验和整理课程交付。

## 信息来源

交接文档只使用当前代码、README、API/测试/演示文档、Day 1-9 报告、现有图片证据和 Git 当前状态作为事实来源。

## 文档结构

1. 交接摘要：项目用途、当前分支、当前总体状态。
2. 已完成模块：按入口、任务、渲染、Web、平台适配和交付材料列出代码位置与已验证能力。
3. 证据分层：明确代码、受控命令、平台 runtime、系统队列、物理或隔离输出五层证据。
4. 未完成事项：按 P0、P1、P2 排序，写出目标、涉及文件、验收标准、风险和禁止误报事项。
5. 不可破坏约束：回环监听、端口段、五状态、单 Worker、任务路径、命令调用、来源授权、错误脱敏、at-least-once 边界。
6. 启动、测试和补验命令：提供 Windows/Linux demo 和全量自动验证；platform 命令只说明前置安全条件。
7. 推荐接手顺序：先获取真实平台证据，再改善文档可用性，最后评估范围外扩展。
8. 可直接交给 Code Buddy 的任务提示词：要求先读文档、建立基线、保持证据口径、每个任务附测试和报告更新。

## P0 交接任务

- Windows 安全虚拟/隔离队列：在明确不会实体出纸且不会弹出阻塞保存对话框的目标上，验证 platform 模式、队列枚举、气球任务、队列接受和隔离输出。
- Linux/CUPS runtime：在真实 Linux 内核环境安装并配置 CUPS client/安全目标，运行测试、提交源码任务并记录 request id 与队列状态。
- 双平台连续录屏：按演示脚本记录系统信息、启动、任务、状态、preview 和队列证据，并在录像中说明成功层级。

## P1 交接任务

- 真人只看 README 启动：全新副本、无口头提示，记录耗时、原始报错、卡点、README 修订与同一人复测。
- 平台证据自动化增量：在安全环境可重复获取队列作业号时，新增 opt-in E2E；不让普通默认测试进入系统队列。

## P2 交接任务

- 仅在课程验收完成并获得许可后，考虑持久化队列数据库、平台作业号持久化、多 Worker、更多纸张模板或 OJ 显式集成。

## 事实边界

- Windows Adapter 受控 runner 已验证，不代表 SumatraPDF 或系统队列实际运行。
- Linux Adapter 已交叉编译，不代表 Linux/CUPS runtime 实测。
- 真实 Chrome PDF 截图存在；Day 7 受限环境下 Chrome E2E 复跑失败必须保留。
- 当前没有双平台系统队列录屏或真人 README 验收记录。
- `demo succeeded` 表示 Fake Adapter 接受调用；`platform succeeded` 表示平台命令返回成功；均不自动等于物理出纸。

## 完成标准

1. 文档能让接手者定位每项工作对应的代码、文档和测试。
2. 每个 P0/P1 任务都有验收标准和失败时不得越界的说明。
3. 没有密钥、账号、绝对用户路径、仓库远程地址或虚构的完成证据。
4. Markdown 结构清晰，`git diff --check` 和文档契约测试通过。
